# Localisation Rules

- Never hardcode user-facing strings in widgets or notifiers. All display strings must use ARB keys via `AppLocalizations` (accessed with `context.l10n.<key>`).
- All three ARB files — `lib/l10n/app_en.arb` (English), `lib/l10n/app_es.arb` (Spanish), and `lib/l10n/app_pt_BR.arb` (Brazilian Portuguese) — must be updated whenever a new string is added. Every key in `app_en.arb` must have a matching key in all other ARB files. `app_pt.arb` (base Portuguese fallback) must also be kept in sync with `app_pt_BR.arb`.
- After editing any ARB file, run `flutter gen-l10n` to regenerate the localisation code.

## Static text rule

Any literal string that appears in the UI — labels, titles, placeholders, button text, empty-state messages, tooltips, error messages — must be defined as an ARB key, even if the app currently only targets one language. This includes:

- Screen and section titles
- Button and tab labels
- Input field hints and placeholders
- Empty-state and loading messages
- Snackbar and error text passed to `snackbarServiceProvider`
- Accessibility labels (`semanticsLabel`, `Semantics.label`)

**Exceptions** — strings that must NOT go through l10n:
- Debug-only strings passed to `AppLogger`
- Asset paths and route constants
- Technical identifiers (API keys, enum names, widget keys)
